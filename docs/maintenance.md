# Maintaining this repo

This config runs on several Macs, Linux boxes and occasionally Windows. It
stays usable only if each fact lives in **one** place and the docs describe
what is actually configured. This page holds the rules and checklists that
keep it that way.

## Rules

1. **One source of truth per fact.** Write a fact down once and generate or
   link to it everywhere else.

    | Fact | Lives in | Everything else |
    | --- | --- | --- |
    | Which tools to install | `BREW_FORMULAE` / `BREW_CASKS` in `bootstrap` | `make tools` prints them. The README's Tools table says what each is *for*, and `make readme` fails if a tool is missing from it |
    | Colours | `theme/palettes/<name>.sh` | per-tool fragments are generated by `theme regen` and gitignored |
    | Plugin versions | `nvim/lua/plugins/*.lua` + `nvim/lazy-lock.json` | `:Lazy restore` reproduces them |
    | Language servers | `SERVERS` in `nvim/lua/plugins/lsp.lua` | not the Mason UI |
    | Files linked outside `~/.config` | `LINKS` in `bootstrap` | |

    The README once kept its own copy of the tool list. It drifted, and was
    missing `gh` and `k9s` while claiming to be in sync. The Tools table that
    replaced it is checked by `make readme` (part of `make docs`), so it
    can't drift silently.

2. **Shared config is portable. Per-machine config goes in a local file.**
   Machine-specific settings go in a gitignored override, not in a
   `hostname` branch:

    - `~/.zshrc.local`: secrets, work-only PATH, per-host aliases
    - `ghostty/local.conf`: macOS 26 glass, per-display font size
    - `alacritty/local.toml`: Windows shell override

3. **Guard every integration.** `.zshrc` wraps each tool in
   `command -v … &&`, so a machine missing `zoxide` still gets a working
   shell. Keep it that way: a new integration must not break a minimal
   server.

4. **Tools write state into `~/.config` too, so `.gitignore` is an
   allowlist.** It starts with `/*`, which ignores everything at the top
   level, then re-includes each tracked file and directory with a `!/<name>`
   line. A new tool's directory never appears in `git status`, so it can't
   be committed by accident.

    - **To track a new tool's config:** read the whole directory first, add
      `!/<dir>/` to the allowlist, and add a section to the right docs page.
    - **State inside a tracked directory** (caches, sockets, logs, auth
      tokens): the allowlist re-includes everything under a directory it
      names, so list that state by path in the second half of
      `.gitignore`, with a comment saying what wrote it (see `herdr/`).

    Never allowlist a directory you haven't read. `stripe/` held live API
    keys, and `github-copilot/` an OAuth token. Check with
    `git ls-files -ci --exclude-standard`, which should print nothing (a
    tracked file that is also ignored).

5. **Private values get `# local-only`.** For a line that belongs on one
   machine but has nowhere else to live, such as a client repo's path in
   `gh-dash/config.yml`, end it with `# local-only`. The `localonly` git
   filter (`.gitattributes`, set up by `make install`) strips those lines
   before git stores the file, so they stay in your working copy and never
   reach a commit. To use it on another file, add
   `<path> filter=localonly` to `.gitattributes`. Check with
   `git show :<path>`, which shows what git will store.

6. **Docs describe what is, not what could be.** If a feature is removed,
   remove its docs in the same commit.

## Where things are documented

| Place | For |
| --- | --- |
| `README.md` | the front door: what this is, quick start, layout, daily commands. Short on purpose |
| `docs/` (this site) | the long form: every tool, every binding, troubleshooting |
| `nvim/README.md` | Neovim's monthly update routine, plugin supply-chain checks, pinned versions |
| `command-cheatsheets/` | references you read in the terminal (`git-commands`, `tmux-commands`…) via `bat` |
| comments in config files | *why* a setting is what it is, next to the setting |

## Checklists

### Adding a CLI tool

- [ ] `brew install <it>` and use it for a while
- [ ] Add it to `BREW_FORMULAE` (or `BREW_CASKS` for macOS GUI apps) in
      `bootstrap`. If the formula and binary names differ, add a `case` line
      next to `neovim)` / `ripgrep)`
- [ ] If it isn't from Homebrew on every machine, add it to `EXTERNAL_TOOLS`
      instead, so `make verify` reports its version
- [ ] Add a row to the **Tools** table in `README.md` saying what it's for.
      `make readme` fails until you do
- [ ] Guard any `.zshrc` integration with `command -v`
- [ ] If it reads config from `~/Library/Application Support` on macOS
      (k9s, lazydocker do), point it back at `~/.config` and note how
- [ ] If it has config worth tracking, add `!/<dir>/` to `.gitignore` and
      list any state it writes inside that directory. Otherwise do nothing:
      the allowlist already ignores it. Then document it on the relevant page

### Adding a docs page

- [ ] Create `docs/<name>.md`, or put it in the matching section folder
- [ ] Add it to `nav:` in `mkdocs.yml`. The build fails if you forget, which
      is intended
- [ ] Use the house conventions: **Ours / Stock** tabs on reference tables,
      keys as `++ctrl+a++`, shell commands without a `$` prompt
- [ ] `make docs`, which runs a strict build. Fix any warning, since each one
      is a dead link or an orphaned page

### Adding a theme, a Neovim plugin, or a Windows tool

- Theme: [Theming → Adding a theme](theming.md#adding-a-theme)
- Plugin: [Architecture → Adding a plugin](neovim/architecture.md#adding-a-plugin)
- Windows: add it to `scripts/windows-setup`, using the same name as in
  `BREW_FORMULAE` where scoop has it

## Monthly routine

About 20 minutes. Do it on your **main** machine, commit, then sync the
others.

1. **Start clean:** `cd ~/.config && git status`. Commit or stash first.
2. **System packages:** `brew update && brew outdated`, then `brew upgrade`.
   Read the list before upgrading: a Neovim major-version jump can break
   pinned plugins (see `nvim/README.md` → *Pinned versions*).
3. **Neovim:** follow the
   [monthly routine](https://github.com/codephilip/dotfiles/blob/main/nvim/README.md#maintenance)
   (`:Doctor`, `:Lazy check`, vet `:Lazy log`, `:Lazy update`,
   `:MasonUpdate`, `:Doctor`), then commit `lazy-lock.json`.
4. **Verify:** `make verify` should show nothing missing and no surprise
   routes.
5. **Docs:** `make docs`. A strict build catches links broken by renames.
6. **Commit and push**, then on each other machine:
   `git pull && make install && nvim "+Lazy restore"`.

## Verifying a change

| Changed | Check with |
| --- | --- |
| `bootstrap` | `make verify` on macOS. For the Linux code path: `docker run --rm -v ~/.config:/c:ro debian:stable-slim bash -c 'cd /c && ./bootstrap --check'` |
| `.zshrc` | `zsh -i -c exit` (no errors), then `/usr/bin/time -p zsh -i -c exit`, which should be about 50 ms ([Troubleshooting](troubleshooting.md#shell-feels-slow-to-start)) |
| Neovim config | `nvim --headless "+Lazy! sync" +qa`, then `:Doctor` |
| theme files | `theme regen && theme show` |
| docs | `make docs` (strict), or `make serve` and look |
