01 — Architecture

How the config is assembled

Four plain Lua modules run in a fixed order, then lazy.nvim takes over and imports one file per concern from lua/plugins/. Nothing is clever: each file owns one subject, and the plugin manager resolves the rest.

Startup path — init.lua to first keystroke
options.lua
Leader key, UI, folding, diagnostics. Must run first — leader is baked into every later mapping.
→
keymaps.lua
Editor-level bindings that need no plugin.
→
autocmds.lua
Yank highlight, cursor restore, disk-change reload, relative numbers.
→
lazy.lua
Bootstraps the manager, imports plugins/, disables unused built-ins.

02 — Load model

Why 27 plugins still start instantly

Only five plugins load when Neovim opens. The other twenty-two sit dormant until something asks for them — a keypress, a command, a filetype, or the VeryLazy event that fires after the UI is already drawn.

Startup cost — eager vs deferred
5 EAGER
22 DEFERRED
colorscheme · treesitter · nvim-tree · lazy · devicons loaded on demand

The four triggers

What wakes a plugin
keys
A mapping is registered as a stub. Press it once and the real plugin loads, then the key fires. This is how fzf-lua, aerial, flash and both AI tools stay out of startup.
cmd
A command name is reserved. Typing :Mason or :Lazygit pulls the plugin in on first use.
event
BufReadPre for LSP and gitsigns, InsertEnter for completion and autopairs — nothing loads before a real buffer exists.
VeryLazy
Fires after the first screen is painted. Statusline, bufferline and which-key appear a few milliseconds late and nobody notices.
03 — Code intelligence

Three layers that understand your code

These are frequently confused. They solve different problems and run independently — treesitter works with no language server attached, and the language server works with no parser installed.

Separation of concerns
Treesitter
Structure of this file. Parses the buffer into a syntax tree on every keystroke. Gives you accurate highlighting, folding, the sticky function header, and the vaf / ]f motions that operate on functions rather than lines. Instant, local, no network.
LSP
Meaning across the project. A background server per language that resolves symbols. Everything that needs to know about other files — go-to-definition, references, rename, diagnostics, call hierarchy — comes from here.
blink.cmp
Presentation. Merges completion candidates from the language server, snippets, open buffers and file paths into one ranked menu. Owns no knowledge of its own.
nvim-lint
Opinions the server does not hold. Runs standalone linters — shellcheck, hadolint, golangci-lint — on write. Silently skips any whose binary is absent.
Where servers come from

mason downloads the binaries; mason-lspconfig enables them. The enable list is an explicit allow-list in lua/plugins/lsp.lua — not true — because mason also holds formatters, and a formatter started as a language server crashes on every launch.

06 — AI workflow

The review loop

The design principle is that Claude never silently rewrites a buffer. Every edit it proposes surfaces as a diff you explicitly accept or reject, in the same window where you were already reading the code.

claudecode.nvim — context in, diff out
Select
vaf grabs a function, or just put the cursor somewhere. The plugin tracks your selection continuously.
Send
Spcas sends the selection; Spcab sends the whole buffer.
Propose
Claude answers in the split. Any file edit opens as a vertical diff against your version.
Review
Read the diff as code, not as chat output. Nothing has been written yet.
Decide
Spcaa accepts, Spcad denies. Only now does disk change.

The full binding set

Spc a cToggle the Claude split
Spc a sSend selection — or, in the tree, add that file
Spc a bAdd the current buffer as context
Spc a rResume an earlier session
Spc a aAccept the proposed diff
Spc a dDeny the proposed diff
Spc a mSwitch model
Spc n nCodeCompanion chat (needs API key)
Why buffers reload on their own

Claude and lazygit both write to disk, not to your open buffer. An autocommand runs checktime on focus and cursor-hold so the buffer refreshes and announces it. Without that, your next :w would overwrite their work with stale text.

07 — Constraints

What will break, and when

Three plugins are pinned to older branches because their defaults now require Neovim 0.12. These are not arbitrary version locks — unpinning them on 0.11.2 breaks the editor on launch.

nvim-treesitterbranch = "master" — main is a full rewrite with an incompatible API. Migrate, don't unpin.
nvim-treesitter-textobjectsbranch = "master" — same rewrite.
aerial.nvimbranch = "nvim-0.11" — the maintained compatibility branch.
blink.cmpversion = "1.*" — v2 is still landing breaking changes.
Known rough edges

No formatter. <leader>cf uses LSP formatting, which is good for Go and Lua and weak for JS, TS and Python. conform.nvim would close this gap.

CodeCompanion is inert until ANTHROPIC_API_KEY is exported. Claude Code needs no key and covers most of the same ground.

s is taken by flash. Use cl for the old substitute-character behaviour.

Icons depend on the terminal, not the config

Every glyph in the statusline, tree and completion menu requires a Nerd Font set in the terminal emulator itself. Warp reads [appearance.text] font_name in ~/.warp/settings.toml; Alacritty reads alacritty.toml. Setting one does nothing for the other.
